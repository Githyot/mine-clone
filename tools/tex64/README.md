# 64x64 textures

The base game's textures are 64x64 per block face, items are 64x64, mob skins have 4 texels per
model pixel (256x512 for the 64x128 layout) and the interface art is drawn at 2 texels per
interface pixel. Everything is generated by code in this folder; no art is copied from Minecraft
or any pack.

## Re-running (after adding blocks, items or mobs)

```
python3 tools/tex64/build.py                 # everything: blocks, items, skins, interface
python3 tools/tex64/build.py --preview /tmp/sheets   # plus contact sheets to look at
python3 tools/tex64/build.py --only stone,dirt       # just a few textures
```

Keep adding new things the way you always did: draw the 16x16 design in `tools/gen_*.py` (or drop
a 16x16 PNG into `packs/vanilla/textures/block|item/`, or a 64x128 skin into `.../entity/`), then
run `build.py`. It copies every 16x16 design into `src16/` (the archive of designs), and writes the
64x64 result back into the pack. A design with a hand-made 64x64 generator uses that; any other is
grown from its 16x16 design by `upscale.py` in the same style. The game also runs if you forget:
16x16 files are simply shown pixel-for-pixel at 64x, just without the extra detail.

After merging branches that both touched textures: take either side's PNGs and run `build.py`.

## Files

| File | What it does |
| --- | --- |
| `style.py` | The style guide as code: light, ramps, contrast limits, tileable noise. |
| `blocks.py` | Hand-made 64x64 blocks (`REGISTRY`). |
| `items.py` | Hand-made items: tools and weapons for every metal, armour icons, ingots, raw ores, gems. |
| `armor3d/` | Armour icons: pictures of each worn 3D piece (horns, crests, colours as on the model), written by `cargo test -p game write_armor_icons -- --ignored` (`crates/game/src/armor_icon.rs`). Re-run it, then `build.py`, after changing a set in `armor_design.rs`. They replace the hand-drawn armour icons of `items.py`/`arms.py`. |
| `toolart.py` | Pickaxes, axes, shovels and hoes with a design per material, Terraria's ores and powered tools (drills, chainsaws, hamaxes). |
| `woods.py` | Every wood's own grain: board layout, figure, knots/pores/rays, bark, end grain, doors, trapdoors. |
| `banners.py` | The long cloth of tall banners (64x128, saved as `NAME_cloth_top/bottom.png`) drawn from each banner's picture; re-run it after changing a banner's design. |
| `boats.py` | One boat per wood: its skin (the wood's planks) and its model in `mobs.ron`, each with a trait of its own. |
| `upscale.py` | 16x16 design -> 64x64 (Scale4x, thin outlines, light and grain, soft contrast). |
| `entities.py` | Mob skins at 4x. Opacity stays exactly the design's so boxes and 3D layers keep their shape. |
| `gui.py` | Hotbar, selection, crosshair, hearts, hunger, armour, air, experience bar, armour slots. |
| `build.py` | Runs all of it. Output is deterministic. |
| `src16/` | Every 16x16 (and 64x128 skin) design. Don't edit the 64x64 PNGs in the pack by hand: edit the design or the generator and re-run. |

## Style rules (short)

1. **One light**: top-left, everything lit the same way; crevices get ambient occlusion.
2. **Material = ramp + albedo + height**, quantised onto a 8-12 step ramp (keeps a hand-painted look).
3. **Hue-shifted ramps**: shadows cooler, lights warmer; very dark and very light carry less colour.
4. **Soft contrast** for natural blocks (HP's request): luminance spread capped by `style.CONTRAST`.
5. **No single-pixel salt noise**: variation comes in 2-6 pixel clusters.
6. **Everything that repeats tiles seamlessly.**
7. **Sprites** get a 2-pixel outline in their own darkest, cooler colour, never black.
8. Natural blocks keep the average colour of their 16x16 design (biome tints and distant terrain
   rely on it).

## Engine side

- One texture array for blocks and items, mipmapped, blended between mip levels.
- `texture_resolution` in settings.ron / Options ("Resolução das texturas"): 16, 32, 64 or 128.
  Lower it on computers with little video memory; our 64x art is shrunk smoothly. Mob skins
  follow it on the next start (1 texel per model pixel at 16x, 4 at 64x).
- Minecraft packs of any resolution still work: a 16x pack is shown pixel-for-pixel (each pack
  pixel becomes 4x4), texture by texture, over our 64x art for anything the pack doesn't have.
- The pixel relief in the terrain shader reads a smaller mip level as texels get smaller than a
  screen pixel, so 64x textures don't shimmer in the distance.

Video memory at 64x: blocks and items ~14 MB, mob skins ~60 MB (with mipmaps).
